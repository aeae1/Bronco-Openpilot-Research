# Contributing evidence

Useful contributions include a reproducible correction to a firmware interpretation, a better instruction decode, a properly identified passive capture, or a source update with an exact revision.

For each technical finding, include the firmware/source identity, address or symbol, method, observed result, and remaining uncertainty. Distinguish an observed vehicle result from a static-code interpretation and from a hypothesis. Explain how the finding changes the current question.

Review identifying information before sharing vehicle data. Prefer a minimal relevant excerpt and metadata over an entire private diagnostic profile. Credit earlier public work and link the exact source where possible.

This project's intended approach preserves factory EPS protections and independent Panda enforcement. Changes that force validity, defeat supervision, increase authority, or substitute a torque interceptor do not demonstrate that approach. Any eventual port belongs in a focused implementation fork with its own validation evidence.
